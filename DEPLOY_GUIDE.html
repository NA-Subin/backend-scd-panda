เอกสารนี้เขียนสำหรับผู้ที่จะนำโค้ดจาก GitHub ไปติดตั้งบนเครื่อง/เซิร์ฟเวอร์ใหม่ทั้งหมด (เช่น ส่งมอบระบบให้ลูกค้าไปดูแลเอง) เรียงเป็นขั้นตอนตามลำดับที่ต้องทำจริง ตั้งแต่เตรียมฐานข้อมูล จนถึงเปิดเว็บใช้งานได้ ใช้เวลาทำจริงประมาณ 30–60 นาทีถ้าเตรียมข้อมูลไว้ครบ

ภาพรวมระบบ

ระบบแบ่งเป็น 2 โปรเจกต์แยกกัน ต้องติดตั้งทั้งคู่และรันคู่กันเสมอ:

  • backend-scd-panda — เซิร์ฟเวอร์ API เขียนด้วย Bun + ElysiaJS เก็บข้อมูลใน PostgreSQL
  • frontend-scd-panda — หน้าเว็บที่ผู้ใช้งานเห็น เขียนด้วย React + MUI หลัง build แล้วเป็นไฟล์ static ล้วน

ระบบเดิมก่อนหน้านี้ใช้ Firebase (Realtime Database + Firebase Auth) ทั้งหมด — เวอร์ชันนี้ย้ายมาใช้ PostgreSQL แล้ว รายละเอียดเชิงเทคนิคว่าทำไมถึงย้าย และวิธี import ข้อมูลล่าสุดจากระบบเดิม (ถ้ายังมีอยู่) มีอธิบายไว้ ในคู่มือผู้ใช้ (/manual.html ของเว็บที่ deploy เสร็จแล้ว หัวข้อ "คำนำ") ไม่ซ้ำเนื้อหาไว้ในนี้อีก

เตรียมฐานข้อมูล PostgreSQL

ระบบต่อฐานข้อมูลโดยกำหนด search_path ไปที่ schema ชื่อ scd_panda โดยเฉพาะ (ไม่ใช่ schema public เริ่มต้น) ต้องสร้างทั้งฐานข้อมูลและ schema ก่อน: 

CREATE DATABASE scd_panda;

\c scd_panda
CREATE SCHEMA IF NOT EXISTS scd_panda;

แนะนำสำหรับใช้งานจริง — สร้างบัญชีเฉพาะสำหรับแอป แทนการใช้ superuser postgres ตรง ๆ:

CREATE ROLE scd_panda_app WITH LOGIN PASSWORD 'ตั้งรหัสผ่านที่นี่';
GRANT ALL ON SCHEMA scd_panda TO scd_panda_app;
GRANT ALL ON ALL TABLES IN SCHEMA scd_panda TO scd_panda_app;
-- สำคัญ: ตารางทั้งหมดจะถูกสร้างขึ้นเองตอนนำเข้าข้อมูล (ขั้นตอนที่ 5) ซึ่งยังไม่มีอยู่ ณ ตอนนี้
ALTER DEFAULT PRIVILEGES IN SCHEMA scd_panda GRANT ALL ON TABLES TO scd_panda_app;
ถ้าข้ามขั้นตอนสร้าง role เฉพาะไปก่อน ใช้ postgres ไปพลาง ๆ ก็ได้ แต่ควรกลับมาทำก่อนใช้งานจริงกับข้อมูลลูกค้า

ตั้งค่า Backend (ไฟล์ .env)

cd backend-scd-panda
cp .env.example .env

แก้ค่าในไฟล์ .env ให้ตรงกับเครื่อง/เซิร์ฟเวอร์จริง:

ตัวแปรคำอธิบาย
PGHOST / PGPORT / PGDATABASE / PGSCHEMA / PGUSER / PGPASSWORDค่าเชื่อมต่อฐานข้อมูลตามที่สร้างไว้ในขั้นตอนที่ 3
JWT_SECRETข้อความลับใช้เซ็นรหัสเข้าสู่ระบบ ต้องตั้งใหม่ทุกครั้งที่ติดตั้งระบบใหม่ สร้างค่าสุ่มปลอดภัยด้วย openssl rand -hex 32
PORTพอร์ตที่ backend จะรัน (ค่าเริ่มต้น 4000)
CORS_ORIGINโดเมนของ frontend จริงที่อนุญาตให้เรียก API นี้ (คั่นด้วยจุลภาคถ้ามีหลายโดเมน)
PG_DUMP_PATH (ไม่บังคับ)path เต็มของโปรแกรม pg_dump ถ้าไม่ได้อยู่ใน PATH ของระบบ — จำเป็นสำหรับฟีเจอร์สำรองข้อมูลอัตโนมัติ

Bun โหลดไฟล์ .env ให้อัตโนมัติ ไม่ต้องติดตั้งแพ็กเกจ dotenv เพิ่ม จากนั้นติดตั้งแพ็กเกจ:

bun install
5

นำเข้าข้อมูลเริ่มต้น

ฐานข้อมูลที่เพิ่งสร้างยังไม่มีตารางใด ๆ เลย เลือกวิธีนำเข้าข้อมูลให้ตรงกับสถานการณ์:

กรณี A — มีไฟล์สำรองข้อมูล (.sql) จากระบบที่ใช้งานอยู่แล้ว แนะนำ

ใช้ตอนย้ายระบบของลูกค้าจริงที่มีข้อมูลอยู่แล้ว ระบบมีฟีเจอร์ "สำรองข้อมูล" ในตัว (ต้องมีสิทธิ์ผู้ดูแลระบบ) ที่สร้างไฟล์ .sql แบบเต็ม (โครงสร้าง + ข้อมูล) เอาไฟล์นั้นมารันกับฐานข้อมูลเปล่าที่เพิ่งสร้างได้เลย:

node run_sql.mjs path/to/backup-file.sql

หรือใช้ psql โดยตรงถ้ามีในเครื่อง: psql -h <host> -U <user> -d scd_panda -f backup-file.sql

แนะนำให้ทดสอบขั้นตอนนี้กับฐานข้อมูลทดสอบสักครั้งก่อนใช้งานจริงกับข้อมูลลูกค้า และอย่าลืมคัดลอกไฟล์ src/schema-manifest.json มาจากระบบต้นทางด้วย — backend จะไม่รู้จักตาราง/คอลัมน์ที่เพิ่ง restore ถ้าไม่มีไฟล์นี้

กรณี B — เริ่มจากศูนย์ด้วยไฟล์ Firebase export ล่าสุด แนะนำ

ใช้ตอนตั้งระบบใหม่ครั้งแรกโดยไม่มีไฟล์สำรอง หน้าเว็บต้องล็อกอินก่อนถึงจะเห็นปุ่มนำเข้าข้อมูล แต่ฐานข้อมูลเปล่ายังไม่มีบัญชีให้ล็อกอิน (ไก่กับไข่) วิธีที่ง่ายที่สุดคือสร้างบัญชีผู้ดูแลระบบชั่วคราวด้วย SQL สั้น ๆ ก่อน แล้วนำเข้าข้อมูลจริงผ่านปุ่มในหน้าเว็บตามปกติ:

psql -h <host> -U <user> -d scd_panda -f sql/bootstrap-admin.sql

(หรือ node run_sql.mjs sql/bootstrap-admin.sql) สร้างบัญชีชั่วคราวไว้ 1 บัญชี: user admin / password ChangeMe123! จากนั้น:

  1. รันเซิร์ฟเวอร์ (ขั้นตอนที่ 6) แล้วล็อกอินด้วยบัญชีชั่วคราวข้างต้นผ่านหน้าเว็บ
  2. กดปุ่ม "นำเข้าข้อมูล JSON (ทับข้อมูลเดิมทั้งหมด)" แล้วเลือกไฟล์ Firebase export ล่าสุด (Firebase Console → Realtime Database → ปุ่มจุดสามจุด ⋮ → Export JSON) — ปุ่มนี้ลบและสร้างทุกตารางใหม่ทั้งหมด บัญชีชั่วคราวจึงหายไปเองพร้อมขั้นตอนนี้ และรหัสผ่านบัญชีจริงทุกบัญชีจะถูกเข้ารหัสให้อัตโนมัติ
  3. ล็อกเอาต์ แล้วล็อกอินใหม่ด้วยบัญชีผู้ดูแลระบบจริงจากระบบเดิม
ต้องใช้ปุ่ม "ทับข้อมูลเดิมทั้งหมด" ไม่ใช่ "เพิ่มข้อมูลใหม่ (ไม่ลบของเดิม)" — ถ้าใช้ปุ่มเพิ่มข้อมูลแทน บัญชีชั่วคราวจะไม่ถูกลบอัตโนมัติ ต้องเข้าไปลบเองทีหลังจากหน้าจัดการพนักงาน

กรณี C — bootstrap ผ่าน command line ล้วน (ไม่อยากเปิดเบราว์เซอร์เลย)

ทำสิ่งเดียวกับกรณี B ในคำสั่งเดียว โดยไม่ต้องล็อกอินผ่านหน้าเว็บเลย:

bun run scripts/bootstrap-uuid-import.js path/to/firebase-export.json

สคริปต์จะสร้างตารางเองตามข้อมูลในไฟล์ พร้อมเข้ารหัสรหัสผ่านพนักงาน/คนขับให้อัตโนมัติ รันครั้งเดียวตอนตั้งระบบใหม่เท่านั้น หลังจากนี้ให้ใช้ปุ่ม "นำเข้าข้อมูล" ในหน้าเว็บสำหรับการนำเข้าเพิ่มเติมในอนาคตแทน

รัน Backend

ทดสอบก่อน:

bun run dev

ทดสอบว่าทำงานถูกต้อง: curl http://localhost:4000/health ควรได้ {"ok":true}

สำหรับใช้งานจริง ต้องรันด้วย bun run start และทำให้รันค้างไว้ตลอดเวลาแม้ปิด terminal หรือเครื่องรีสตาร์ท:

  • Linux (แนะนำ): pm2 start "bun run start" --name scd-panda-backend หรือสร้างเป็น systemd service
  • Windows: ใช้ NSSM ห่อคำสั่งเป็น Windows Service หรือใช้ pm2 เช่นกัน

ตั้งค่า Frontend

cd frontend-scd-panda
npm install
cp .env.local.example .env.local

แก้ไฟล์ .env.local ให้ชี้ไปที่ backend จริง:

REACT_APP_API_URL=https://api.โดเมนลูกค้า.com
ค่านี้ถูกฝังเข้าไปในไฟล์ที่ build ออกมาแบบถาวร ถ้าเปลี่ยนที่อยู่ backend ภายหลัง ต้อง build ใหม่ทุกครั้ง แก้แค่ .env.local เฉย ๆ โดยไม่ build ใหม่จะไม่มีผลอะไรเลย

อย่าลืมตั้งค่า CORS_ORIGIN ฝั่ง backend ให้ตรงกับโดเมนที่จะ deploy หน้าเว็บนี้ด้วย ไม่งั้นเบราว์เซอร์จะบล็อกการเรียก API ทั้งหมด

Build เว็บสำหรับใช้งานจริง:

npm run build

จะได้โฟลเดอร์ build/ ที่มีไฟล์ static ล้วน พร้อมเอาไปวางบนเว็บเซิร์ฟเวอร์ใดก็ได้ (คู่มือใช้งาน /manual.html ติดไปด้วยอัตโนมัติ อยู่ใน public/ อยู่แล้ว ไม่ต้องทำอะไรเพิ่ม)

8

Deploy โฟลเดอร์ build/

วิธีที่ 1 — เว็บเซิร์ฟเวอร์ทั่วไป (nginx/Apache/IIS) แนะนำสำหรับเซิร์ฟเวอร์ลูกค้าเอง

คัดลอกเนื้อหาในโฟลเดอร์ build/ ไปไว้ในโฟลเดอร์ที่เว็บเซิร์ฟเวอร์ชี้ถึง แล้วตั้งค่าให้ rewrite ทุก path ที่ไม่ตรงกับไฟล์จริงไปที่ index.html (จำเป็นเพราะเป็น SPA) ตัวอย่าง nginx:

server {
  listen 80;
  server_name app.โดเมนลูกค้า.com;
  root /var/www/html;
  index index.html;

  location / {
    try_files $uri /index.html;
  }
}

แนะนำให้ตั้ง HTTPS ผ่าน nginx (เช่นด้วย Let's Encrypt/Certbot) แทนการเปิด HTTP เปล่า ๆ ออกอินเทอร์เน็ต

วิธีที่ 2 — Firebase Hosting

repo มีไฟล์ firebase.json/.firebaserc เตรียมไว้แล้ว

.firebaserc ปัจจุบันชี้ไปที่โปรเจกต์ Firebase เดิมของผู้พัฒนา — ห้ามใช้ค่านี้ต่อกับลูกค้ารายใหม่โดยตรง จะ deploy ทับเว็บเดิมโดยไม่ตั้งใจ ต้องสร้างโปรเจกต์ Firebase ของลูกค้าเองก่อนเสมอ
npm install -g firebase-tools
firebase login
firebase use --add   # เลือกโปรเจกต์ Firebase ใหม่ของลูกค้า
firebase deploy --only hosting

ดูแลรักษาต่อเนื่องหลังส่งมอบ

  • สำรองข้อมูลอัตโนมัติ — ระบบสำรองข้อมูลให้เองทุกวันตี 1 (เก็บย้อนหลัง 30 วัน) ทำงานทันทีที่เซิร์ฟเวอร์ backend รันอยู่ ไม่ต้องตั้งค่าเพิ่ม แค่ต้องแน่ใจว่าเซิร์ฟเวอร์รันค้างไว้ตลอดเวลาจริง (ดูขั้นตอนที่ 6)
  • อัปเดตโค้ดในอนาคต — git pull ที่ repo ที่เกี่ยวข้อง แล้วรัน bun install/npm install ใหม่ถ้ามีแพ็กเกจเพิ่ม จากนั้น restart backend หรือ build+deploy frontend ใหม่แล้วแต่ฝั่งที่แก้
